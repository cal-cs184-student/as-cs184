Overview

In this homework, I developed a geometric modeling tool capable of evaluating smooth curves and surfaces while supporting dynamic mesh manipulations. I started by implementing de Casteljau's algorithm for Bezier curve and surface evaluation, then moved into mesh processing using the half-edge data structure. Core operations include area-weighted vertex normals for smooth shading, edge flips, and edge splits with boundary support. Finally, I implemented a robust mesh upsampling pipeline using the Butterfly subdivision scheme. What stood out most was witnessing how simple linear interpolations on 1D curves naturally extend into complex 3D surface subdivision. Throughout the process, I saw that the underlying mathematics carries significant geometric weight in practice.

Task 1: Bezier Curves with 1D de Casteljau Subdivision

De Casteljau's algorithm works by progressively blending control points together until a single point on the curve is produced. Starting with n control points and a parameter t, each pass takes every neighboring pair of points and mixes them together using the formula (1 - t) * p[i] + t * p[i+1], shrinking the list by one each time. This continues until only one point is left, which is exactly where the curve sits at that value of t. To implement this, we wrote evaluateStep to handle one pass of this blending process on a list of 2D points, returning the smaller intermediate list. Evaluating the full curve is then just a matter of feeding the output back into evaluateStep over and over until nothing remains but the final point.

Task 2: Bezier Surfaces with 2D de Casteljau Subdivision

Bezier surfaces work by breaking the problem down into two separate passes of the same 1D algorithm we already know. A Bezier surface is defined over an nxn grid of control points, where each row forms a curve running in the u direction. To find a point on the surface at (u, v), we start by sweeping through every row and running de Casteljau on it using u, which boils each row down to a single point. Once every row has been collapsed, we are left with n points that now stretch in the v direction. At that point, we just treat those points as a fresh set of control points and run de Casteljau one more time using v, which gives us our final surface point. The implementation pretty much mirrors this logic directly we first collapse each row at u, collect the resulting points into a new list, and then collapse that list at v. It was actually satisfying to see how cleanly the 1D algorithm we already built could be reused twice to handle the full 2D surface case.

Task 3: Area-Weighted Vertex Normals

To get smooth vertex normals, we walk around all the triangles neighboring a vertex using the half-edge structure and accumulate their contributions. For each triangle we come across, we grab its three vertex positions and compute the cross product of two of its edge vectors. The neat thing here is that we get area weighting for free the magnitude of a cross product naturally grows with the triangle's area, meaning bigger triangles automatically pull the normal more in their direction without any extra work on our end. After going all the way around the one-ring and summing everything up, we just normalize the result to get a clean unit normal. The difference compared to flat shading is pretty visible instead of each face looking like a hard polygon, the surface starts to look genuinely smooth because each vertex is now blending in the influence of all its neighboring faces.

Task 4: Edge Flip

To implement edge flip, we first checked that the edge was not on the boundary, then mapped out all the nearby half-edges, vertices, and faces, and rewired all the pointers to form the two new triangles without adding or removing anything from the mesh. Debugging took a while we kept seeing a strange gap appear in the teapot after a flip, and it turned out we were reading the wrong vertex from a half-edge, which made two triangles shrink to nothing and disappear. Drawing everything out on paper with our variable names labeled on each edge and vertex made the mistake easy to spot and fix.

Task 5: Edge Split

To implement edge split, we first checked that the edge was interior, then collected all the surrounding half-edges, vertices, edges, and faces. We created a new vertex at the midpoint by averaging the two endpoints, and allocated the additional mesh elements needed to form four triangles: one new vertex, three new edges, six new half-edges, and two new faces. We then carefully rewired every pointer's twin, next, vertex, edge, and face and to make sure each of the four new triangles formed a valid closed loop. The hardest part was keeping track of all the pointer updates; a single wrong next pointer would cause the traversal to break or crash entirely. To debug, we drew the before and after configuration on paper with every variable labeled, which made it easy to catch any missed or incorrect connections.

Extra Credit: Boundary Edge Splits

To support edge splits on boundary edges, we first checked if either adjacent face was a boundary face. Since only the interior face gets split, we allocated fewer new elements than usual such as one new vertex at the midpoint, one new edge, three new half-edges, and one new face. We then updated all the pointers so the interior side formed two valid triangles while the boundary side just adjusted to include the new midpoint vertex. The trickiest part was making sure the boundary half-edges still connected in a proper loop after the split, since breaking that cycle causes traversal to fail.

Task 6: Subdivision for Mesh Upsampling (with Butterfly Extra Credit)

Loop subdivision splits each triangle into four smaller triangles and updates vertex positions using weighted averages. To ensure correct weight calculations, all new positions were computed on the original mesh before any topology changes. For existing vertices we used (1 - n * u) * original_position + u * neighbor_sum, and for new edge midpoint vertices we used 3/8 * (A + B) + 1/8 * (C + D). We then split every original edge, assigned cached positions to new vertices, and flipped any new edge connecting an original and new vertex to restore correct connectivity. The result is a mesh that converges to a smooth surface with each subdivision level, as seen below.

When subdividing a cube with Loop subdivision, the result is asymmetric because each face is initially split into two triangles with a single diagonal, and those diagonals break the cubic symmetry. To fix this, we pre-process the cube by splitting each diagonal edge on every face before applying subdivision, so that each face is divided into four symmetric triangles rather than two asymmetric ones. This gives the mesh an X-shaped triangulation on every face, ensuring that the Loop subdivision weights are applied symmetrically across all six faces. The result is a cube that subdivides into a symmetric rounded shape, as the averaging weights now respect the underlying symmetry of the geometry.

Extra credit: Boundary Support

To support meshes with boundary, we added special cases for boundary vertices and edges. Boundary edge midpoints use 1/2 * (A + B) instead of the interior formula, and existing boundary vertices use 1/8 * left + 3/4 * original + 1/8 * right, where left and right are the neighboring boundary vertices along the boundary loop.

Extra credit: Additional Subdivision Schemes

We implemented the modified Butterfly scheme as an additional triangle subdivision method. Unlike Loop subdivision which minimizes energy, Butterfly is an interpolating scheme, original vertices keep their exact positions while new edge midpoints are computed using an 8-point stencil : 1/2 * (v0 + v1) + 1/8 * (v2 + v3) - 1/16 * (v4 + v5 + v6 + v7), where v0 and v1 are the shared edge endpoints, v2 and v3 are the opposite vertices of the two adjacent triangles, and v4 through v7 are the remaining neighbors of v0 and v1. The result is a smoother interpolating surface compared to standard Butterfly while still passing through all original vertices.
